# RAON Agent Factory Product Brief

## 타깃·문제·가치

- 타깃: 기존 웹·업무 시스템에 반복 업무를 수행하는 AI 실행 흐름을 붙이려는 조직
- 문제: 범용 대화형 AI는 실제 시스템 권한, 실행 상태, 결과 검증, 운영 기록과 분리되기 쉽다.
- 가치: 한 업무를 작게 정하고 연결 범위와 권한을 합의한 뒤, 실행·검증 기록을 남기며 확장한다.
- CTA: `AI 에이전트 구축 상담`. 온라인 접수가 닫힌 경우 개인정보 입력칸을 렌더하지 않는다.

## 상품

1. 업무 한 개 실증: 대상 업무·성공 기준·권한 경계를 정하고 실행 결과를 확인한다.
2. 맞춤형 AI 에이전트 구축: 검증된 흐름을 기존 시스템과 연결한다.
3. 구축 에이전트 운영·개선: 요청과 실패 기록을 바탕으로 변경하고 다시 검증한다.

가격, 기간, 절감률, 매출, SLA는 승인된 근거가 없어 공개 문구에 포함하지 않는다.

## Public · Auth · Admin 경계

- Public: 사업 홈, 기존 Community/Notice/Q&A/Search, 상담 config 조회. 상담 제출은 same-origin, 유효한 동의 설정, `Idempotency-Key`가 모두 필요하다.
- Auth: 기존 G7 회원·계정 URL을 유지한다. `/ai`는 별도 승인 사용자 흐름이며 일반 사용자에게 AI 실행 권한을 새로 열지 않는다.
- Admin: 신규 상담은 공개 비활성·항상 비밀인 `raon-consultations` board에서 기존 admin 역할과 board 권한으로 조회·메모·상태를 처리한다. 과거 product admin API는 410과 공식 board admin 경로를 반환한다.

## IA·사용자 여정

홈 순서(0.5.0)는 Hero → 두 제품 증거(RAON Hub·MOBILE_STOCK) → 구매 범위 3행 → 적합성·차이 → 두 사례 검증 범위 → 절차·신뢰 → 상담이다.
홈 섹션 바로가기 줄은 없고, 휴대폰·태블릿 홈은 기본 헤더와 드로어 하나로 탐색한다. Hero 행동은 상담 config 가 정한다 —
접수 닫힘(기본·실패 포함)이면 사례·도입 절차, 열림이 확인될 때만 상담이 주 행동이다. 하단에서 Community와 로그인 사용자용 `/ai`로 이동하고,
공지·Q&A·검색은 푸터가 담는다. 세부는 [0.5.0 홈 제품화 기록](home-productization-0.5.0.md).
서비스·사례·원칙 3개 정보 화면과 개인정보·커뮤니티·AI 작업공간·오픈소스 4개 정책 화면은 직접 URL과 새로고침을 지원한다.

상담 여정은 config 확인 → 접수 가능 시에만 입력 → 별도 개인정보 동의 → 제출 → 저장 성공 뒤 접수 번호 표시다.
같은 내용 재시도는 같은 멱등성 키를 사용하고, 다른 내용에 같은 키가 쓰이면 409로 거부한다.

## 자체 구현 사례

- MOBILE_STOCK (0.5.0 홈 공개 범위는 독립 검토 PASS_PUBLIC 증거로 제한 — [0.5.0 기록](home-productization-0.5.0.md) "Wave E"): 모바일 모의투자 제품을 여러 AI 개발 Provider의 요청 단위 구현·검증 흐름으로 만든 자체 사례다. 실거래, 투자 성과, 고객 납품은 주장하지 않는다.
- RAON Hub/GNUBOARD7: G7 코어를 수정하지 않고 제품 홈과 승인 사용자용 AI 작업공간을 확장 모듈로 붙인 자체 사례다. 상용 트래픽, 장기 운영, 외부 고객 운영은 검증했다고 주장하지 않는다.

## 화면 Acceptance

- 360/390/412px 및 desktop에서 수평 overflow가 없고, 터치 대상·키보드 포커스·reduced-motion을 확인한다.
- 직접 URL, 새로고침, SPA 이동에서 title/meta/CSS와 기존 URL이 유지된다.
- 접수 비활성 시 “온라인 상담 접수 준비 중”과 안전한 공개 설정 후 활성화한다는 사실만 표시하며 임의 연락처를 만들지 않는다.
- 201/200/409/422/429/503, 네트워크 오류, 연속 클릭, 동일 재시도에서 성공·오류 상태를 구분하고 입력 보존 여부를 검증한다.

## Provider 경계

- 신규 상담은 G7 공식 `PostService`를 통해 공개 비활성·항상 비밀·관리자 전용 board에 저장한다. 기존 전용 상담 테이블은 migration을 바꾸지 않고 legacy 감사 대상으로만 유지한다.
- 상담 payload를 일반 공개 게시판, 검색 인덱스, 범용 알림 payload 또는 AI 실행 요청으로 자동 전달하지 않는다.
- G7 코어와 공식 템플릿은 수정하지 않고 Layout Extension, 모듈 route/config/middleware/provider, 공식 asset lifecycle을 사용한다.
